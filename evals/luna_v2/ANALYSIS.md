# 技能价值与 v1 短板审计

目前没有证据证明 OwnVoice 比直接写清偏好更好。技能没有添加新的模型能力；可检验的潜在价值是复用约束与工作流程、从材料归纳风格、减少遗漏及用户反复交代规则的成本。这些目前都是待验证假设。

v1 的短板：

1. 短函数和短段落远离真实任务复杂度。相反偏好被完整翻译成了变量长度、句数和段落指令，强模型遵循后很容易全部通过，形成天花板。
2. 列表表达式、变量长度和段落数主要测字面指令响应，不能代表风格、清晰度或采用意愿。没有真正测试从样本归纳约定、迁移到新内容，以及不把样本事实带进新任务。
3. 三种情况均只有一次生成，任务共享模板，缺少真正复杂的版本冲突、来源归属、未知值、接口兼容和跨文件行为约束。
4. 工具被禁用且只许输出成品，技能中“运行检查、比较前后行为”的流程没有得到验证。此前 29 项软件测试验证的是工具边界，并不是这些工作流程的实际效果。
5. 数字和字符串检查无法可靠识别谁需要执行动作、引用是否支持断言、单位是否被误解、否定和证据强度是否保持。英文邮件的六个歧义输出来自同一个案例，不能算六个独立失败。
6. 邮件补丁后的两个样例显式写明职责，无旧版或清单基线，不能把通过归因为补丁效果。该补丁只能称为候选防护规则。
7. 没有“普通提示＋等价检查清单”基线，无法判断潜在收益来自可复用提醒还是特殊的适配机制；输入、模型和验证成本也没有一起比较。
8. 历史运行未报告实际模型标识；当前 CLI 默认配置为 Astra，不能追认历史调用。新轮必须显式指定 Luna，保存请求模型、推理设置及可用返回元数据，禁止回退。

## 本轮要区分的结论

| 结果 | 允许的解释 |
| --- | --- |
| 技能优于普通提示，但与完整清单持平 | 有流程复用价值，没有特殊能力优势证据 |
| 技能在相同信息与资源下优于完整清单 | 出现增益候选，仍需独立任务和真实使用者确认 |
| 三组接近且均能完成复杂任务 | 本轮未显示额外收益，不能继续靠简单通过率宣传效果 |
| 技能引入义务、虚构事实或破坏接口 | 内容回归优先处理，风格分不能抵消 |
| 评分工具无法识别已知错误 | 先修检查工具和任务歧义，不把它解释成模型成功 |

不挑选让 OwnVoice 获胜的任务，不把未提供的事实藏成评分要求，不削弱基线，不以相同任务反复改提示后当作留出成功。开发与留出分开；只允许基于开发失败的一次有依据修改，保留失败和旧候选。
