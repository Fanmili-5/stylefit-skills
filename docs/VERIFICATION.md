# Output and verification contracts

The helper runs locally without model calls. The recommended suite installer provides an isolated Python environment with `jsonschema==4.25.1` and its pinned dependencies. It does not change global Python or Codex settings.

```sh
stylefit verify --artifact draft.json --schema schema.json --constraints constraints.json --report checks.json
```

Inside a copied/installed skill, use its launcher instead of requiring a global command:

```sh
python3 path/to/stylefit-email/scripts/verify.py --artifact draft.json --schema schema.json --constraints constraints.json --report checks.json
```

The launcher accepts both the shorthand above and an explicit `verify` subcommand. If the managed helper is unavailable it exits 2 with `not_run`; it never silently marks the artifact verified. The helper never rewrites input, removes extra braces, renames keys or fills facts.

## Results and exit codes

- `0`: all declared required checks passed.
- `1`: the candidate failed a check, or a required review is `not_run`.
- `2`: contract, environment or report-path errors prevented validation.

Reports contain `schema_version`, `status`, `ready_for_delivery`, `checks`, `blocking_issues`, `verification_gaps` and the SHA-256 of the exact UTF-8 artifact. These statuses apply only to the supplied contract. With neither schema nor assertions, only nonempty text is checked; this is not content validation. Syntax/schema/finite tests cannot establish arbitrary-code equivalence or prose truth.

## Schema

Use JSON Schema Draft 2020-12. Every nested representation that a consumer requires must be declared. The verifier checks the schema itself and rejects remote references, duplicate JSON keys and non-finite JSON constants. References within the same document are supported. `format` is deliberately rejected: use explicit date assertions below rather than assuming an annotation executes validation. Natural prose is not forced into JSON when the user has not asked for it.

## Explicit constraints v1

```json
{
  "schema_version": 1,
  "assertions": [
    {"id": "sample-count", "op": "equal", "path": "/facts/n", "expected": 92},
    {"op": "equal", "path": "/facts/independent_n", "expected": null},
    {"op": "unit_conversion", "path": "/facts/latency_ms", "source_value": 0.42, "factor": 1000, "tolerance": 1e-9},
    {"op": "date", "path": "/ledger/deadline", "expected": "2027-03-15", "formats": ["%Y-%m-%d", "%d %B %Y"]}
  ],
  "semantic_review": {"required": true, "status": "not_run"}
}
```

Assertions use JSON pointers. Supported operations are `equal` (including optional numerical tolerance), `unit_conversion` (factor and optional offset/tolerance), `date` (explicit permitted formats), `contains`, `not_contains`, `regex` and `source_ids` (an explicit allowed ID list). Unknown operations/fields are contract errors. Null, boolean and numeric values are distinguished. Dictionary key order is not part of factual equality; array order is.

Date comparisons normalize the explicitly listed formats. Timezone-aware datetimes are compared in UTC; naive datetimes retain their literal local time. Supply `%z` when timezone comparison is required. This does not perform unconstrained natural-language date extraction or impose ISO substrings on prose.

Expectations must come from the task, authoritative source data or a separately checked contract. A ledger generated by the same candidate is not a gold reference. Assertions check that ledger; body/source correspondence still needs direct review. After an actual review, an attestation may include `status: passed|failed`, `source: human|model` and nonempty `evidence`. The verifier records that attestation; it does not authenticate the reviewer or turn it into mechanical proof. Never call an automated review human review.

One feedback-based revision is the default workflow. Recheck the changed artifact, preserve failures and report unresolved checks instead of using unlimited successful-answer rerolls.
